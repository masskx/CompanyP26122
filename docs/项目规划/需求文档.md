# 设备预测性维护与智能助手需求文档

> 文档状态：需求初稿  
> 更新日期：2026-11-04  
> 适用对象：业务方、产品、前端、后端、测试与系统集成人员

## 1. 文档目的与边界

本文定义设备预测性维护与智能助手两条业务线的目标、范围、功能要求、业务规则和验收标准。

用户端与 MES 主服务器之间的鉴权、通信协议、会话接入和接入页面由其他团队负责。本文只描述本项目的业务需求以及与主服务器之间的能力边界，不设计用户如何登录或如何与主服务器通信。

技术实现、接口协议、RAG 服务组成、数据存储和部署方式见 [设计文档](./设计文档.md)。

## 2. 项目目标

本项目面向核电站 MES 工作站，在现有监测总览能力之上新增两条业务线：

- **设备预测性维护**：汇总设备健康状态，结合隔离室、备电系统及历史运行数据分析异常趋势，给出可追溯的风险依据、维护建议和置信度。
- **智能助手**：基于固定、预先整理并版本化发布的站内知识库与只读业务数据，回答设备、运行和维护问题，并支持生成分析结果与报告。

项目应满足以下总体目标：

- 降低设备运行风险识别的遗漏率，并让结论可以追溯到具体数据和知识来源。
- 让用户能够通过自然语言查询制度、手册、历史案例和只读业务数据。
- 所有分析和建议仅用于辅助人工判断，不自动执行设备操作、工单流转或报警确认。
- 系统能够在国产算力服务器、隔离网络和固定知识库条件下稳定运行。

## 3. 角色与职责边界

| 角色 | 职责 |
| --- | --- |
| 业务用户 | 查看设备健康状况、发起分析、查看证据和报告、使用智能助手 |
| 授权维护人员 | 人工核查预测性维护建议，并按线下流程决定是否执行维护 |
| 运维发布人员 | 准备固定知识语料、构建版本化知识包并执行索引发布和回滚 |
| 主服务器团队 | 负责用户鉴权、权限校验、审计、请求转发和业务数据接口 |
| 算力服开发与运维 | 负责维护分析编排、完整 RAG 服务、模型服务和算力服运行 |

本项目不负责：

- 监测总览、报警确认和其他既有 MES 页面的业务实现。
- 主 MES 的账号体系、组织权限、设备主数据和业务数据库建设。
- 用户端与主服务器之间的鉴权、通信协议、会话接入和页面交互设计。
- 知识文档的作者维护、审批、用户上传、删除和在线管理界面。
- 现场设备采集链路、设备控制、工单派发和自动维修执行。
- 模型分析结果的自动审批。

## 5. 功能需求

### 5.1 设备预测性维护

| 编号 | 需求 |
| --- | --- |
| FR-MA-01 | 用户可按站点和设备分类查看全站设备健康概览。 |
| FR-MA-02 | 设备健康状态至少支持 `normal`、`watch`、`inspect`、`insufficient_data` 四类。 |
| FR-MA-03 | 用户可针对隔离室、备电系统或指定设备发起分析，并选择分析时间范围。 |
| FR-MA-04 | 系统应使用设备快照、历史运行数据和历史维护记录进行统计与规则判断。 |
| FR-MA-05 | 系统应展示分析阶段、最终状态、风险等级、关键证据、数据缺口、建议和置信度。 |
| FR-MA-06 | 数据不足时必须返回 `insufficient_data`，不得用模型推测补齐缺失数据。 |
| FR-MA-07 | 维护建议必须标记是否需要人工确认，并明确不触发设备控制或工单流转。 |
| FR-MA-08 | 用户应能查看已持久化的分析结果，并在流式连接中断后恢复。 |

### 5.2 智能助手

| 编号 | 需求 |
| --- | --- |
| FR-AS-01 | 用户可围绕设备、运行、维护和 MES 使用问题进行自然语言提问。 |
| FR-AS-02 | 助手应能区分知识问答、设备状态查询和需要组合分析与报告的请求。 |
| FR-AS-03 | 助手可以调用只读业务工具获取设备状态或历史数据，不得提供写操作。 |
| FR-AS-04 | 助手应基于固定知识库和业务数据生成回答，并附可定位的引用来源。 |
| FR-AS-05 | 回答过程应展示面向用户的阶段状态、工具调用摘要和引用，不展示模型隐式思维链。 |
| FR-AS-06 | 知识无命中、权限不足、设备不存在或数据不足时，应明确说明原因，不得编造事实或操作指令。 |
| FR-AS-07 | 会话应能够恢复上下文，并保留会话、消息、引用和反馈记录。 |

### 5.3 固定知识库与 RAG

| 编号 | 需求 |
| --- | --- |
| FR-KB-01 | 知识库只使用预先整理、审批完成并版本化发布的固定语料。 |
| FR-KB-02 | 每个知识发布版本应包含完整语料、发布清单、版本信息和校验信息。 |
| FR-KB-03 | 发布版本内的知识语料保持固定，运行时不接收用户上传、删除或在线入库。 |
| FR-KB-04 | 知识更新应支持离线构建、校验、原子切换和回滚，不中断现有查询。 |
| FR-KB-05 | 智能助手必须经过查询向量化、向量召回、rerank 和上下文组装后生成回答。 |
| FR-KB-06 | 每次回答应固定使用一个知识索引版本，不得在一次查询中混用新旧语料。 |
| FR-KB-07 | 引用的知识文档必须能够定位到具体来源、版本和章节或片段。 |

### 5.4 报告与可追溯性

| 编号 | 需求 |
| --- | --- |
| FR-RP-01 | 用户可从授权范围内的历史数据和分析结果生成报告。 |
| FR-RP-02 | 报告应保留生成时间、统计范围、来源数据、知识引用和模型版本。 |
| FR-RP-03 | 维护分析、助手会话、知识引用和关键操作应支持审计追踪。 |
| FR-RP-04 | 日志和界面不得暴露完整服务令牌、数据库凭据或未经批准的敏感数据。 |

## 6. 业务规则

- 确定性规则优先：阈值、连续异常、数据缺失和趋势统计由可测试的业务规则完成，模型负责解释和组织结果。
- 证据优先：事实性回答必须基于设备数据或知识库引用，不得凭模型常识补造站内事实。
- 数据不足不猜测：缺少关键数据时输出明确的数据缺口或 `insufficient_data`。
- 人工最终确认：维护建议、报告结论和模型分析结果仅供人工核查。
- 只读工具：智能助手只拥有业务数据读取能力，不拥有设备控制、报警确认或工单写入能力。
- 固定知识：知识文档不通过用户端或主服务器上传，不接受运行时在线修改。
- 版本一致：一次查询只使用一个知识索引版本，引用的文档版本必须与本次查询版本一致。

## 7. 非功能需求

### 7.1 安全与合规

- 用户鉴权和权限判断由主服务器负责，算力服只接受受信任的主服务器调用。
- 算力服内部模型、embedding、rerank 和向量数据库不得直接暴露给用户端。
- 跨主机通信使用 HTTPS，密钥和令牌通过受控机制注入。
- 知识语料和业务数据按来源、密级和权限范围控制引用。

### 7.2 可用性与可靠性

- 单次模型故障或 RAG 依赖故障不得导致整站服务不可用。
- 数据读取、模型调用、向量检索和 rerank 应设置超时、有限重试和并发控制。
- SSE 断线后应能通过持久化结果恢复分析内容。
- 结果回写和任务创建应支持幂等，避免重复记录。

### 7.3 性能与容量

首版在以下硬件基线上运行：

- 鲲鹏 920-Smart，32 核。
- 128 GB DDR4 2933。
- 4 TB M.2。
- 昇腾 Atlas 300I A2 64 GB × 1。
- 1250 W ATX 电源。
- Qwen3-30B-A3B，首版按 W8A8 量化版本验证。

具体上下文长度、并发数、首 token 延迟和 token/s 目标由业务方确认，并通过实机压测固化。单卡容量不足以支持 30B 模型 BF16 生产部署。

### 7.4 离线和国产化

- 系统应支持隔离网络部署，不依赖公网服务。
- 镜像、模型、embedding 模型、rerank 模型、知识语料和依赖应支持离线导入与版本校验。
- 关系库、向量库、对象存储和应用运行时应在 ARM64 环境完成兼容性验证。

### 7.5 可维护性与可观测性

- RAG 知识包应支持版本发布、校验、回滚和问题定位。
- 运维应能查看模型、embedding、rerank、向量库和索引版本的可用性。
- 应记录检索、rerank、模型生成和回写等关键阶段的耗时与错误。

## 8. 验收标准

### 8.1 预测性维护

- 全站设备能按四类健康状态正确分类。
- 隔离室和备电分析能使用指定时间范围的数据，输出证据、建议、置信度和数据缺口。
- 数据不足、设备不存在和权限不足时返回明确结果。
- 分析建议不能触发任何设备操作或自动工单。
- 分析结果在流式连接中断后可以恢复查看。

### 8.2 智能助手与 RAG

- 助手能区分知识问答、设备状态查询和报告请求。
- 事实性回答经过召回和 rerank，并包含可定位引用。
- 知识无命中时明确返回无依据结果，不编造引用。
- 固定知识包可以离线构建、校验、原子切换和回滚。
- 单次查询不会混用新旧知识版本。
- embedding、rerank 或向量库不可用时返回明确错误或已批准的降级结果。

### 8.3 安全与可运维性

- 用户端无法直接访问算力服内部模型、embedding、rerank 或向量库。
- 无有效服务令牌或来源非法的请求被拒绝并记录审计。
- 用户端和主服务器接口中不存在知识文档上传、删除、审核或索引管理入口。
- 系统能够在隔离网络完成启动、知识发布、健康检查和故障恢复。

## 9. 依赖与待确认事项

| 类别 | 待确认内容 | 影响 |
| --- | --- | --- |
| 外部接口 | 主服务器 SSE 代理、服务令牌轮换、设备数据和回写接口 | 决定联调时间与数据可用性 |
| 硬件 | CANN、NPU 驱动、鲲鹏平台版本和磁盘冗余方案 | 决定镜像、设备挂载和可靠性 |
| 模型容量 | 单卡 W8A8 下的上下文长度、并发、延迟和吞吐 | 决定是否需要增加推理卡或缩小模型 |
| 知识范围 | 固定语料范围、版本频率、密级和权限规则 | 决定知识包和检索过滤条件 |
| RAG 部署 | embedding/rerank 使用 CPU 还是 NPU | 决定内存/显存配额和检索延迟 |
| 数据库 | 关系库、向量库和对象存储的具体产品与版本 | 决定兼容性、备份和索引发布方案 |
| 数据规则 | 设备数据频率、异常阈值、历史窗口和质量规则 | 决定维护分析的准确性 |
| 报表 | 报告格式、模板、存储期限和下载权限 | 决定报告生成和存储方案 |

## 10. 里程碑

| 阶段 | 目标 |
| --- | --- |
| M0：需求与接口确认 | 固化业务范围、主服务器边界、模拟数据和最小端到端链路 |
| M1：预测性维护 | 完成健康概览、隔离室/备电分析、结果回写和证据展示 |
| M2：智能助手 | 完成固定知识包编译、embedding、向量检索、rerank、只读工具、引用和会话 |
| M3：算力适配 | 在目标 ARM64 + 昇腾环境完成模型、RAG 链路和并发压测 |
| M4：联调与上线 | 完成安全测试、故障演练、离线安装包、灰度发布和回滚验证 |
