# 鲲鹏昇腾服务器环境配置手册

环境安装命令。代码部署见 [代码部署指南](./代码部署指南.md)。

以下命令默认在 root shell 中执行；保留 `sudo` 不影响执行，也可以直接去掉。

参数执行规则：

1. 参数只在对应章节执行：网络在第 2 章，DSH/uv 在第 4 章，模型在第 8 章，vLLM 在第 9 章。
2. `export` 只影响当前终端；新 SSH 会话需要重新加载参数文件。
3. vLLM 参数持久化到 `/etc/mes/vllm.env`，供启动脚本和 systemd 使用。
4. 所有 `<...>` 必须替换后再执行后续命令。
5. API Key 和密码不得写入 Git、Markdown 或 DSH 工作区。

## 1. 系统与桌面

```bash
uname -m
cat /etc/os-release
uname -r
systemctl get-default
sudo systemctl set-default graphical.target
systemctl get-default
```

**操作**：确认 CPU、系统和内核，并把默认启动级别设为桌面。  
**预期**：架构为 `aarch64`；最后输出 `graphical.target`。

```bash
sudo timedatectl set-timezone Asia/Shanghai
sudo systemctl enable --now chronyd
```

**操作**：设置时区并启用时间同步。  
**预期**：`timedatectl` 显示 Asia/Shanghai，`chronyd` 为 active。

```bash
sudo tee /etc/sysctl.d/99-mes-ai.conf >/dev/null <<'EOF'
vm.max_map_count=262144
vm.swappiness=1
fs.file-max=1048576
EOF
sudo sysctl --system
```

**操作**：写入大模型和容器常用的内核参数。  
**预期**：`sysctl --system` 返回成功，三项配置均为指定值。

```bash
sudo tee /etc/security/limits.d/99-mes-ai.conf >/dev/null <<'EOF'
* soft nofile 1048576
* hard nofile 1048576
EOF
```

**操作**：提高文件描述符上限。  
**预期**：重新登录后 `ulimit -n` 显示 `1048576`。

## 2. 网络

### 2.1 网络参数

在服务器本地桌面终端或 KVM 中执行：

```bash
cat >/root/network.env <<'EOF'
SERVER_IP="192.168.50.20"
SERVER_CIDR="$SERVER_IP/24"
GATEWAY_IP="192.168.50.1"
DNS_IP="<内网DNS>"
EOF
set -a
source /root/network.env
set +a
```

**操作**：保存并加载网络参数。  
**预期**：`SERVER_CIDR`、`GATEWAY_IP` 和 `DNS_IP` 与参考服务器同网段配置一致。

参数依据：

| 参数 | 依据 |
|---|---|
| `SERVER_IP` | 新服务器未占用 IP |
| `SERVER_CIDR` | IP/掩码；不是 `/24` 时显式填写前缀 |
| `GATEWAY_IP` | 内网默认网关 |
| `DNS_IP` | 参考服务器实际使用的 DNS |

### 2.2 网络检查

```bash
ip -br link
ip -4 addr
ip route
ping -c 2 "$GATEWAY_IP"
getent hosts archive.kylinos.cn
curl -I --max-time 10 https://registry.npmmirror.com
curl -I --max-time 10 https://www.modelscope.cn
```

**操作**：检查内网路由、DNS 和国内软件源连通性。  
**预期**：网关可 ping，`getent` 返回 IP，HTTP 响应为 200/301/302。

以下命令直接在参考服务器本地执行，不需要从新服务器访问参考服务器：

```bash
hostname
ip -br link
ip -4 addr show
ip route show default
cat /etc/resolv.conf
nmcli -t -f NAME,DEVICE,TYPE,STATE connection show --active
nmcli -t -f NAME,TYPE,STATE connection show --active |
awk -F: '$2=="802-3-ethernet" {print $1}' |
while IFS= read -r connection_name; do
  echo "### $connection_name"
  nmcli -f ipv4 connection show "$connection_name"
  nmcli -g ipv4.addresses,ipv4.gateway,ipv4.dns \
    connection show "$connection_name"
done
```

**操作**：读取参考服务器的网卡、IP/掩码、默认网关、DNS 和 IPv4 配置。  
**预期**：输出类似 `192.168.50.10/24`、`192.168.50.1` 和 DNS 地址；新服务器沿用
相同网段、网关和 DNS。

配置示例：

```text
参考服务器：192.168.50.10/24
默认网关：  192.168.50.1
DNS：       192.168.50.2
新服务器：  192.168.50.20/24
```

**操作**：只为新服务器分配一个未占用 IP，掩码、网关、DNS 和 VLAN 与参考服务器保持一致。  
**预期**：新服务器能访问同网段服务器、网关和国内软件源。

在新服务器配置前检查候选 IP 未被占用：

```bash
ping -c 3 192.168.50.20
ip neigh show 192.168.50.20
```

**操作**：检查准备分配给新服务器的 IP。  
**预期**：配置前没有稳定响应；若已有主机响应，必须改用其他未占用 IP。

不要直接复制参考服务器的 IP、MAC、主机名或连接 UUID。需要复制的是网段、掩码、网关、DNS、
VLAN 和路由策略。

```bash
nmcli con show
nmcli con mod "<连接名>" \
  ipv4.method manual \
  ipv4.addresses "$SERVER_CIDR" \
  ipv4.gateway "$GATEWAY_IP" \
  ipv4.dns "$DNS_IP"
nmcli con up "<连接名>"
ip route
```

**操作**：配置固定 IP、网关和 DNS。  
**预期**：`ip route` 有一条默认路由，地址和网关与现场规划一致。

## 3. SSH

```bash
mkdir -p /root/.ssh
chmod 700 /root/.ssh
```

**操作**：准备 root 的 SSH 密钥目录。  
**预期**：`/root/.ssh` 存在，权限为 `700`。

在 Windows 执行：

```powershell
ssh-keygen -t ed25519 -C "mes-ops" -f "$HOME\.ssh\mes_ops_ed25519"
Get-Content "$HOME\.ssh\mes_ops_ed25519.pub" |
  ssh root@192.168.50.20 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

**操作**：生成 Windows 密钥并上传到 root。  
**预期**：之后可不输入密码执行 `ssh root@192.168.50.20`。

```bash
passwd root
```

**操作**：设置或更新 root 登录密码。  
**预期**：两次密码输入一致，系统提示密码更新成功。

```bash
sudo tee /etc/ssh/sshd_config.d/99-mes-hardening.conf >/dev/null <<'EOF'
PermitRootLogin yes
PasswordAuthentication yes
KbdInteractiveAuthentication yes
PubkeyAuthentication yes
UsePAM yes
AllowUsers root
ClientAliveInterval 60
ClientAliveCountMax 6
EOF
sudo sshd -t
sudo systemctl enable --now sshd
sudo systemctl reload sshd
```

**操作**：写入 SSH 配置、检查语法并重新加载 sshd。  
**预期**：`sshd -t` 无输出，sshd 正常运行。

```bash
sudo sshd -T | grep -E \
  'permitrootlogin|passwordauthentication|kbdinteractiveauthentication|allowusers'
```

**操作**：只允许 root 使用密码、键盘交互或密钥登录。  
**预期**：显示 `permitrootlogin yes`、`passwordauthentication yes`、
`kbdinteractiveauthentication yes`、`allowusers root`；新终端可用
`ssh root@192.168.50.20` 登录。

## 4. Node.js 与 DSH

### 4.1 DSH/uv 参数

```bash
cat >/root/dsh-uv.env <<'EOF'
NODE_VERSION="24.22.3"
DSH_VERSION="0.2.2-rc.1"
UV_VERSION="0.13.8"
UV_PYTHON_DIR="/opt/uv/python"
UV_PYTHON_INSTALL_DIR="/opt/uv/python"
UV_TOOL_DIR="/opt/uv/tools"
UV_TOOL_BIN_DIR="/usr/local/bin"
EOF
set -a
source /root/dsh-uv.env
set +a
```

**操作**：保存并加载 Node.js、DSH 和 uv 参数。  
**预期**：Node.js 版本不低于 24.9，DSH 和 uv 使用固定版本。

参数依据：

| 参数 | 依据 |
|---|---|
| `NODE_VERSION` | DSH 要求 Node.js 24.9+，当前固定 24.22.3 |
| `DSH_VERSION` | 固定生产验证版本，不填写 `latest` |
| `UV_VERSION` | 记录并固定 uv 发行版本 |
| `UV_*` | 系统级 uv Python、工具和命令目录 |

### 4.2 安装 Node.js 24

服务器在线下载：

```bash
sudo mkdir -p /data/pkg/node
curl -L --fail -o "/data/pkg/node/node-v${NODE_VERSION}-linux-arm64.tar.xz" \
  "https://npmmirror.com/mirrors/node/v${NODE_VERSION}/node-v${NODE_VERSION}-linux-arm64.tar.xz"
```

**操作**：从 npmmirror 下载 Node.js ARM64 压缩包。  
**预期**：文件下载到 `/data/pkg/node/`，大小正常。

Windows 下载：

```powershell
curl.exe -L --fail -o "D:\offline\node-v24.22.3-linux-arm64.tar.xz" `
  "https://npmmirror.com/mirrors/node/v24.22.3/node-v24.22.3-linux-arm64.tar.xz"
Get-FileHash "D:\offline\node-v24.22.3-linux-arm64.tar.xz" -Algorithm SHA256
```

**操作**：服务器下载失败时，在 Windows 下载 Node.js。  
**预期**：生成 tar.xz 文件和 SHA-256。

内网中转机：

```bash
scp /path/to/node-v24.22.3-linux-arm64.tar.xz root@192.168.50.20:/data/pkg/node/
```

**操作**：由内网中转机上传 Node.js。  
**预期**：文件位于 `/data/pkg/node/`。

服务器：

```bash
sudo mkdir -p "/opt/node/${NODE_VERSION}"
sudo tar -xJf "/data/pkg/node/node-v${NODE_VERSION}-linux-arm64.tar.xz" \
  -C "/opt/node/${NODE_VERSION}" --strip-components=1
sudo ln -sfn "/opt/node/${NODE_VERSION}" /opt/node/current
sudo ln -sfn /opt/node/current/bin/node /usr/local/bin/node
sudo ln -sfn /opt/node/current/bin/npm /usr/local/bin/npm
sudo ln -sfn /opt/node/current/bin/npx /usr/local/bin/npx
node -v
npm -v
```

**操作**：解压 Node.js 并建立全局软链接。  
**预期**：`node -v` 输出 `v24.22.3`，`npm -v` 正常输出版本。

### 4.3 服务器在线安装 DSH

```bash

  --omit=dev \
```

**操作**：从 npmmirror 安装 DSH 并注册命令。

### 4.5 准备 root 的 DSH 目录

```bash

```

**操作**：创建 root 的 DSH 配置目录和工作目录。  
**预期**：`/root/.dsh` 和 `/root/dsh-workspace` 存在。

### 4.6 DSH systemd

直接手动运行：

```bash
cd /root/dsh-workspace
export DSH_HOME=/root/.dsh
dsh web --host 127.0.0.1 --port 3080 --no-open
```

**操作**：以 root 身份直接启动 DSH。  
**预期**：终端保持运行并打印 `http://127.0.0.1:3080/` 启动地址。

需要后台常驻时使用 root 的 systemd 服务：

```bash
sudo tee /etc/systemd/system/dsh-web.service >/dev/null <<'EOF'
[Unit]
Description=DeepSeek Harness Web UI
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
Group=root
WorkingDirectory=/root/dsh-workspace
Environment=DSH_HOME=/root/.dsh
Environment=PATH=/opt/node/current/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=/usr/local/bin/dsh web --host 127.0.0.1 --port 3080 --no-open
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now dsh-web
sudo systemctl status dsh-web --no-pager
sudo journalctl -u dsh-web -n 100 --no-pager
```

**操作**：配置并启动 root 身份的 DSH Web 服务。  
**预期**：服务为 active；日志打印 `http://127.0.0.1:3080/` 启动地址。

## 5. 麒麟源和基础软件


**操作**：备份 APT 配置并刷新国内麒麟源索引。  
**预期**：`apt update` 最终返回成功，无 404、签名或架构错误。

配置单位批准的麒麟国内源后执行：

```bash
sudo apt install -y \
  openssh-server ca-certificates curl wget git vim nano tar xz-utils unzip \
  net-tools lsof htop tmux chrony \
  build-essential dkms "linux-headers-$(uname -r)" \
  nginx docker.io docker-compose-plugin
```

**操作**：安装编译、网络、SSH、Nginx 和 Docker 基础工具。  
**预期**：`git`、`curl`、`gcc`、`make`、`dkms`、`nginx`、`docker` 均可执行。

```bash
docker version
docker compose version
```

**操作**：检查 Docker 客户端和 Compose 插件。  
**预期**：输出版本号，`docker compose version` 返回 v2.x。

### 5.1 安装 uv

```bash
curl -LsSf https://astral.sh/uv/install.sh |
  sudo env UV_UNMANAGED_INSTALL=/usr/local/bin sh
uv --version
```

**操作**：把 uv 安装到系统路径 `/usr/local/bin`，供后续服务用户共用。  
**预期**：`uv --version` 输出 `uv 0.13.x`。

服务器无法在线安装时，先按第 10.2 节 `EXT-UV` 准备资源，再执行：

```bash
sudo tar -xzf /data/pkg/uv/uv-aarch64-unknown-linux-gnu.tar.gz \
  -C /usr/local/bin --strip-components=1
uv --version
uvx --version
```

**操作**：用 Windows 下载的 ARM64 压缩包安装 uv。  
**预期**：`uv --version` 和 `uvx --version` 均输出版本号。

### 5.2 用 uv 安装 Python 3.12

```bash
source /root/dsh-uv.env
sudo mkdir -p "$UV_PYTHON_DIR" "$UV_TOOL_DIR" "$UV_TOOL_BIN_DIR"
sudo tee /etc/profile.d/uv.sh >/dev/null <<EOF
export UV_PYTHON_INSTALL_DIR="$UV_PYTHON_DIR"
export UV_TOOL_DIR="$UV_TOOL_DIR"
export UV_TOOL_BIN_DIR="$UV_TOOL_BIN_DIR"
EOF
source /etc/profile.d/uv.sh
sudo env UV_PYTHON_INSTALL_DIR="$UV_PYTHON_INSTALL_DIR" uv python install 3.12
uv python find 3.12
```

**操作**：写入系统级 uv 路径，并由 uv 下载和托管 Python 3.12。  
**预期**：`uv python find 3.12` 输出 `/opt/uv/python/.../bin/python3.12`。

```bash
sudo env UV_PYTHON_INSTALL_DIR="$UV_PYTHON_DIR" uv python list --only-installed
```

**操作**：查看 uv 已安装的 Python。  
**预期**：列表中存在 Python 3.12。

Python 下载失败时，按第 10.3 节 `EXT-PY` 准备安装包，再使用 uv
本地镜像或内网制品地址安装。

## 8. vLLM 镜像和模型

### 8.1 模型参数

```bash
cat >/root/model.env <<'EOF'

```

**操作**：保存并加载 Qwen3-14B、Qwen3-30B-A3B 和 bge-m3 参数。

参数依据：

| 参数 | 依据 |
|---|---|

## 12. 部署约定

1. **网络边界**：服务器最终只在内网提供业务，不向互联网开放业务端口。
2. **外网下载链路**：外网 Windows 不连接服务器。Windows 下载完成后，先转交内网中转机，再由内网中转机上传服务器。
3. **服务器联网**：服务器可访问互联网，优先使用麒麟源、npmmirror、ModelScope、国内 Docker 镜像等国内源。
4. **离线补件**：只有境外站点、国内镜像缺失或服务器下载失败的制品，才走外网 Windows 备料。
5. **桌面会话**：服务器保留银河麒麟桌面，默认 target 固定为 `graphical.target`。
6. **文档边界**：本手册只负责服务器环境和模型运行时；业务代码、数据库、Nginx 和联调按《代码部署指南》执行。
7. **端口**：vLLM 仅监听 `127.0.0.1:8000`，Embedding 仅监听 `127.0.0.1:8002`，DSH 仅监听 `127.0.0.1:3080`，Controller 在受控内网监听 `8001`。
8. **DSH 访问**：DSH 不直接暴露到内网网卡，统一通过 SSH 隧道访问。
9. **镜像选型**：A2/910B 使用 A2 镜像；300I DUO/200I Pro 的 310P 才使用 `-310p` 镜像。
10. **制品记录**：镜像 digest、模型仓库 ID、revision、驱动版本和 Windows 传输文件 SHA-256 必须留档。
11. **密钥**：`/etc/mes/vllm.env` 权限固定为 `0600`，密钥不得写入 Git、Markdown 或 DSH 工作区。
12. **Python 管理**：Python 3.12 由 uv 安装和检索；Python 工具使用 `uv tool`，业务环境使用 `uv venv` 和 `uv sync`。
13. **服务器账号**：服务器只使用 root；DSH 由 root 直接启动，配置目录为 `/root/.dsh`，工作目录为 `/root/dsh-workspace`。
