## 1. Python · 流式输出

```bash
pip install -U openai
```

```python
# chat_stream.py
import sys
from openai import OpenAI, APIError

BASE_URL = "http://172.16.103.222:8000/v1"
API_KEY  = "sk-vllm-demo-2026"
MODEL    = "qwen3-14b"

client = OpenAI(base_url=BASE_URL, api_key=API_KEY, timeout=180, max_retries=2)


def chat_stream(messages, max_tokens=512, temperature=0.7, on_delta=None):
    """流式调用，边收边回调；返回拼好的完整文本。

    messages: [{"role": "user", "content": "..."}]
    on_delta: 每收到一段文本调用一次；传 None 就只攒完整结果
    """
    stream = client.chat.completions.create(
        model=MODEL,
        messages=messages,
        max_tokens=max_tokens,
        temperature=temperature,
        stream=True,
        # Qwen3 默认会先输出一大段思考过程，业务调用建议关掉
        extra_body={"chat_template_kwargs": {"enable_thinking": False}},
    )

    parts = []
    for chunk in stream:
        if not chunk.choices:
            continue
        delta = chunk.choices[0].delta
        if delta and delta.content:
            parts.append(delta.content)
            if on_delta:
                on_delta(delta.content)
    return "".join(parts)


if __name__ == "__main__":
    question = "用三句话解释什么是 KV Cache，以及它为什么吃显存。"
    try:
        answer = chat_stream(
            [{"role": "user", "content": question}],
            max_tokens=512,
            on_delta=lambda d: (sys.stdout.write(d), sys.stdout.flush()),
        )
        print("\n" + "-" * 40)
        print("完整回答：", answer)
    except APIError as e:
        print(f"接口报错: {e.status_code} {e.message}")
```

**只想要完整结果、不要打字机效果**：去掉 `on_delta`，直接用返回值

```python
answer = chat_stream([{"role": "user", "content": "总结一下这段话"}])
print(answer)
```

**多轮对话**：历史自己带，服务端不存状态

```python
messages = [{"role": "system", "content": "你是工业质检领域的专家。"}]
messages.append({"role": "user", "content": "金属表面划痕用什么算法检测？"})
reply = chat_stream(messages, on_delta=print)
messages.append({"role": "assistant", "content": reply})   # 下一轮带上
```

## 2. Node.js · 流式输出

要求 Node 18+（SDK 依赖内置 fetch）。

```bash
npm i openai
```

```js
// chat_stream.mjs
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://172.16.103.222:8000/v1",
  apiKey: "sk-vllm-demo-2026",
  timeout: 180000,     // 毫秒
  maxRetries: 2,
});

const MODEL = "qwen3-14b";

/**
 * 流式调用，边收边回调；返回拼好的完整文本。
 * @param {Array<{role: string, content: string}>} messages
 */
async function chatStream(messages, { maxTokens = 512, temperature = 0.7, onDelta } = {}) {
  const stream = await client.chat.completions.create({
    model: MODEL,
    messages,
    max_tokens: maxTokens,
    temperature,
    stream: true,
    // Qwen3 默认会先输出一大段思考过程，业务调用建议关掉
    chat_template_kwargs: { enable_thinking: false },
  });

  let text = "";
  for await (const chunk of stream) {
    const delta = chunk.choices?.[0]?.delta?.content;
    if (delta) {
      text += delta;
      onDelta?.(delta);
    }
  }
  return text;
}

const answer = await chatStream(
  [{ role: "user", content: "用三句话解释什么是 KV Cache，以及它为什么吃显存。" }],
  { maxTokens: 512, onDelta: (d) => process.stdout.write(d) },
);

console.log("\n" + "-".repeat(40));
console.log("完整回答：", answer);
```

> **CommonJS 项目**（`require` 写法）：第一行换成 `const OpenAI = require("openai");`，
> 文件用 `.js`，并把最外层 `await` 包进 `(async () => { ... })();` 里。

**典型用法：转成 SSE 给前端**（Express 示例）

```js
app.post("/api/chat", async (req, res) => {
  res.setHeader("Content-Type", "text/event-stream; charset=utf-8");
  res.setHeader("Cache-Control", "no-cache");
  res.setHeader("Connection", "keep-alive");

  await chatStream(req.body.messages, {
    onDelta: (d) => res.write(`data: ${JSON.stringify({ delta: d })}\n\n`),
  });

  res.write("data: [DONE]\n\n");
  res.end();
});
```

## 4. 工具调用（LangGraph / function calling）

服务端启动参数已带 `--enable-auto-tool-choice --tool-call-parser hermes`，所以任何 OpenAI 兼容的 agent 框架（LangGraph、LlamaIndex、AutoGen、自己写的 ReAct 循环）都能直接绑工具，不用额外网关。

> 服务端没开这两项时，请求里一带 `tools` 就报 400：
> `"auto" tool choice requires --enable-auto-tool-choice and --tool-call-parser to be set`

### 4.1 安装

```bash
pip install -U langgraph langchain-openai
```

### 4.2 LangGraph ReAct Agent（已实测可跑）

```python
# langgraph_tool_demo.py
import json
import os

from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langgraph.prebuilt import create_react_agent

BASE_URL = os.getenv("VLLM_BASE_URL", "http://172.16.103.222:8000/v1")
API_KEY = os.getenv("VLLM_API_KEY", "sk-vllm-demo-2026")
MODEL = os.getenv("VLLM_MODEL", "qwen3-14b")


@tool
def get_weather(city: str) -> str:
    """查询指定城市的实时天气。"""
    return json.dumps({"city": city, "temp": "3℃", "weather": "晴"}, ensure_ascii=False)


llm = ChatOpenAI(
    model=MODEL,              # 必须等于服务的 --served-model-name，写错是 404
    base_url=BASE_URL,        # 结尾要带 /v1
    api_key=API_KEY,
    temperature=0,
    timeout=120,
    max_retries=1,
    # Qwen3 默认先输出 <think>…</think>，开着会污染 content 且更易跑偏，业务场景关掉
    extra_body={"chat_template_kwargs": {"enable_thinking": False}},
)

agent = create_react_agent(llm, [get_weather])

if __name__ == "__main__":
    result = agent.invoke({"messages": [{"role": "user", "content": "北京现在天气怎么样？"}]})
    for msg in result["messages"]:
        print(f"--- {msg.type} ---")
        print("content:", msg.content)
        if getattr(msg, "tool_calls", None):
            print("tool_calls:", msg.tool_calls)
```

实际输出（human → 模型发起调用 → 工具返回 → 模型总结）：

```
--- human ---
content: 北京现在天气怎么样？
--- ai ---
content:
tool_calls: [{'name': 'get_weather', 'args': {'city': '北京'}, 'id': 'chatcmpl-tool-…', 'type': 'tool_call'}]
--- tool ---
content: {"city": "北京", "temp": "3℃", "weather": "晴"}
--- ai ---
content: 北京现在的天气是晴天，温度为3℃。
```

### 4.3 不装框架，直接 curl 联调

只验证服务端有没有把工具调用解析出来：

```bash
curl -s http://172.16.103.222:8000/v1/chat/completions \
  -H "Authorization: Bearer sk-vllm-demo-2026" \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen3-14b","tool_choice":"auto","max_tokens":256,
       "messages":[{"role":"user","content":"北京现在天气怎么样？"}],
       "tools":[{"type":"function","function":{"name":"get_weather",
                 "description":"查询指定城市的实时天气",
                 "parameters":{"type":"object","properties":{"city":{"type":"string"}},"required":["city"]}}}],
       "chat_template_kwargs":{"enable_thinking":false}}'
```

返回里 `finish_reason` 是 `tool_calls`、`message.tool_calls[0].function.arguments` 是 JSON 字符串，就说明通了：

```json
{"finish_reason":"tool_calls",
 "message":{"content":null,
            "tool_calls":[{"id":"chatcmpl-tool-...","type":"function",
                           "function":{"name":"get_weather","arguments":"{\"city\": \"北京\"}"}}]}}
```

流式（`"stream":true`）同样支持，工具调用会以 `delta.tool_calls` 增量吐出来，LangGraph 的流式输出不受影响。

### 4.4 踩坑清单

| 现象 | 原因 / 处理 |
| --- | --- |
| 400 `"auto" tool choice requires ...` | 服务端少了 `--enable-auto-tool-choice --tool-call-parser hermes` |
| 404 `model not found` | `model=` 写的不是 `qwen3-14b` |
| 401 或连不上 | `base_url` 要带 `/v1`，`api_key` 要带 |
| 模型只回一段带 `<tool_call>` 的文字、没有 `tool_calls` | 同第一条，解析器没开 |
| `content` 里混着 `<think>…</think>` | 没关 `enable_thinking` |
| agent 跑几轮就 400 超长 | 上下文只有 16384，工具 schema + 历史很吃 token，先裁剪历史 |

> 版本差异：langgraph 1.x 里 `create_react_agent` 已迁到 `langchain.agents.create_agent`（旧导入还能用，会有 Deprecation 警告，需要装 `langchain`）。langchain-openai ≥ 0.2 才支持 `extra_body` 参数，老版本改用 `model_kwargs={"extra_body": {…}}`。
>
> 换模型时解析器跟着换：Qwen3-Coder 用 `--tool-call-parser qwen3_coder`，Qwen2.5 系列仍旧用 `hermes`。

## 5. 参数速查

| 参数 | 建议 | 说明 |
| --- | --- | --- |
| `stream` | `true` | 首字快、体验好；后端批处理可以 `false` |
| `max_tokens` | 256–1024 | 别开 4096+，会长时间占显存，别人只能排队 |
| `temperature` | 0.7 对话 / 0.1 抽取 | 事实型任务调低 |
| `enable_thinking` | `false` | 开着会多烧 2–3 倍 token，且先输出 `` |
| `timeout` | ≥ 60s | 长回答要留够，SDK 默认偏短 |
| 上下文 | ≤ 16384 | 超了直接 400，报错里写得很清楚 |
| `tool_choice` | `auto` | 带 `tools` 时用，见第 4 节 |

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| `401 Unauthorized` | `api_key` 写错，或没带 `Authorization: Bearer ...` |
| `This model's maximum context length is 16384 tokens` | 输入太长，拆多轮或先摘要 |
| 第一条请求等了 20 多秒 | 服务刚启动的预热，之后同长度 1–2s |
| 输出开头一堆 `…` | `enable_thinking` 没关 |
| 带 `tools` 报 400 `"auto" tool choice requires ...` | 服务端缺 `--enable-auto-tool-choice --tool-call-parser hermes`，见第 4 节 |
| `404 model not found` | `model` 必须填 `qwen3-14b` |
| `Connection refused` | 服务没起，看第 7 节 |
| 两个人同时问，后一个明显慢 | 长上下文时并发约 1，会排队，属正常 |
